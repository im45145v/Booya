DemoLens 0.5.0 adds updates from inside the app, a rewrite of how keys are captured and shown, recording a take into the middle of a project, projects saved as folders with autosave, and a measured answer to the audio lag report.

Most of the macOS, Windows and Linux capture code here compiles on CI but has **not been run by the author on real hardware**. See "Check it on your Mac" and "Honest limits".

## What is new
- **Updates inside the app.** Settings > About and updates > **Check for updates**, a banner with **Install and restart**, and a switch for checking at launch. Update files are signed and checked against a key built into the app. A copy installed from a `.deb` or `.rpm` is pointed to the download page. See `docs/UPDATES.md`.
- **Keys, not just letters.** Modifiers (Ctrl, Alt, Option, Shift, Cmd, Win), Fn, Caps Lock, F1 to F12, media keys, Cmd-click and Option-drag are captured and shown. On a Mac you can show the symbols (⌘ ⌥ ⇧ ⌃) or words, per project. Typing stays hidden if you ask. The letters you type are still never stored.
- **Record a take into the middle.** Under the preview: **Record here** inserts a new take at the playhead; **Re-record clip** records over the selected clip. The captions, zooms, callouts, blur boxes and shapes after that point move to match. **Project > Import a video clip at the playhead** does the same from a file. The old recording is kept, so Undo works.
- **Projects.** Save writes a `.demolens` folder with the recording and everything in it, so it can be moved or shared. A **Project** menu (Save as, Duplicate, Open a project folder), recent projects on the start screen, a **Locate** dialog for missing files, autosave every 15 s with a recovery offer after a crash. See `docs/PROJECTS.md`.
- **Edit more text.** Callout text can now be changed in place. `docs/EDITING.md` lists every text element and where to change it.
- **More control over auto zoom.** **Zoom hold** and **Group clicks within** under Style > Zoom. A 1.25x clip speed.

## Sound against picture
You reported the audio lagging. A flash and beep test signal now runs through every stage on every OS in CI. The file stages (editor preview proxy, export, cut then export, a microphone that opened 350 ms late) are within 17 ms on Ubuntu, macOS and Windows, with at most 4 ms of drift. The problem was not Mac only:
- The editor preview followed the video clock, not the sound. It now follows the sound.
- On Linux, recording the microphone inside the screen ffmpeg put the sound 471 ms early in the test. A separate microphone file with wall clock stamps, joined at the end, brings that to 118 ms, 353 ms better, and part of the rest is the test's own start skew. Windows used the same design and now uses the new one. macOS already had it.
- `demolens syncprobe` prints the table. Results and method are in `docs/SYNC.md`.

## Fixes
- Callout text could only be deleted and re-added. It can be edited.
- CI now installs ffmpeg before the tests, so the media tests run on macOS and Windows too.

## Check it on your Mac
1. Update from 0.4.2 if you can: Settings > About and updates > Check for updates. This is the first release the updater can deliver, so 0.4.2 itself has no updater and must be replaced by hand once.
2. After the update macOS may ask for Screen Recording, Microphone and Input Monitoring again, because the app is signed ad hoc. Allow them and reopen DemoLens.
3. Record 30 s with the microphone and Keys on. Press Fn, Option, Ctrl, F-keys and a media key. Run `demolens verify` on the file and send me the output, plus whether the sound looks late when you play it.
4. Move the playhead to the middle, press **Record here**, record a few seconds, stop. Check the end of the project moved and nothing is out of step. Then **Undo**.
5. Save, quit, reopen from the recent list. Change something, wait 15 s, force quit, reopen, and accept the recovery.

## Honest limits
- No macOS capture sync number exists. CI runners cannot capture a screen or microphone.
- Windows has no audio capture test. Only its screen clock was checked (14 flashes, worst deviation 38 ms).
- Linux with microphone and system audio together still mixes them in one process.
- Media keys, Fn on Windows and Linux, and AltGr were written from the platform documentation and not tried on hardware.
- The export leads the sound by about 16 ms on every OS. It is constant and below anything visible.
- The splice, project and update screens were checked as logic and on CI, not driven by hand in a window. The splice keeps sync inside budget on test files.
- Per clip settings: only speed. A splice ignores the new take's webcam and hides the project's webcam, because one offset cannot cover a gap.
- Updates need the signing key on the release machine. If the release was built without it, update files are signed afterwards with `scripts/sign-release.py`.
- Still ad hoc signed on macOS, no notarization: Gatekeeper will warn on first launch, as before.
