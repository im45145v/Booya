DemoLens 0.5.2 shows full keyboard shortcuts, keeps the window and panels on screen, lets you drag the panel sizes, makes captions start when you start talking, stops fast speech from losing words, brings back editor sound on macOS, and retunes auto zoom so it zooms only when something matters.

Parts of this release (the macOS key tap, key names on Windows and Linux, touch, the macOS sound fix) are built and tested on CI but have **not been run on real hardware**. See "Honest limits".

## Key overlay shows the whole shortcut
- Cmd, Ctrl, Alt or Win plus a key is now shown as one shortcut, for example Cmd+W or Ctrl+T, instead of the modifier alone.
- Shift is shown for shortcuts and for symbols, and plain typing stays as typed text.
- On macOS the key tap now reports the real key with its modifiers. Option and Ctrl combos use US keyboard position names.

## Window and panels
- The window opens inside the visible screen, and shrinks if it is too big for the display. It is clamped again when the display changes.
- The side panel and the timeline now have **draggable splitters**. Drag with a mouse or finger, use the arrow keys (Shift for bigger steps, Home to reset), or double click or double tap to reset. Sizes are remembered and given back when the window grows.

## Captions
- **Start on the voice.** A word is moved to when the voice actually starts, so a recording with 2 seconds of silence before you speak no longer gets captions that begin early. A test with 2 seconds of leading silence guards this.
- **Fast talking.** Long recordings are listened to in overlapping pieces, the pieces are merged so no word is counted twice, and any gap where speech was heard but no words were found is listened to again. Words cut off at a piece edge are ignored in favour of the other piece.

## Editor sound on macOS
- If the web view cannot play the compact sound file, the editor switches by itself to a plain WAV copy, and says so if both fail.
- The sound is unlocked by your first click or key press in the editor, which is what WebKit needs before it will play.
- A new check notices when playback starts but the clock does not move and switches to the fallback.

## Auto zoom, retuned
Zoom now scores each moment and only zooms when the score is high enough:
- A marker you placed always counts most. Then the first key of typing, a click that you aimed at, a place where the cursor rested, and last a click with no aiming.
- Clicks that are navigation (a tab switch, Cmd+Tab, arrows), quick repeats, right clicks, drags, clicks at the very edge, and clicks after the cursor jumped across the screen never zoom.
- Zooms stay put for nearby events, pan for events that are a bit further away, and zoom out when the next event is far away. Zooms are kept apart so the picture never pumps.
- New **Style** choice: Subtle, Normal and Lively. Normal is the default.
- The zoom eases with a spring curve, calmer at the start and the end.
- The full rules are in docs/EDITING.md under "Auto zoom: when it zooms".

## Honest limits
- The macOS key tap, key names on Windows and Linux, and touch were verified by CI compile only, not on real hardware.
- macOS may ask again for Input Monitoring after each update because the app is signed ad hoc. This is the likely reason shortcuts showed only the modifier on a Mac.
- Option and Ctrl combos on non-US layouts use US position names. On Windows, AltGr can look like Ctrl+Alt.
- Linux uses X11 through rdev. Wayland is not supported.
- Scroll events are not in the log, so scrolling never triggers a zoom.
- The small target check is a guess from the cursor settling, because the log has no information about element size.
- Windows system audio capture is not implemented yet.
- WKWebView and Safari are not available to us, so the macOS sound fix is tested in Chrome and by reasoning only.
