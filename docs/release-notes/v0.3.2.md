DemoLens 0.3.2 makes the Area tab of the source picker work like a screenshot tool: hover a window and click to snap to it.

Like the releases before it, this was built and tested on CI and a Linux box. It has **not been run on a Mac or a Windows PC by the author**. The macOS and Windows window frames are the first thing to check, see "Check it on your Mac".

![Hovering a window in the Area tab](https://raw.githubusercontent.com/im45145v/DemoLens/main/docs/media/v032-area-snap.png)

## New
- **Hover to snap** (Area tab). Move over the screenshot and the window under the pointer is highlighted with a label showing the app name and its size. **Click** to select that window's exact frame as the area. **Drag** still draws a free rectangle.
- **Aspect presets keep working.** With 16:9, 4:3, 1:1, 4:5 or 9:16 chosen, a click takes the largest rectangle of that shape, centred in the window, and the highlight shows it before you click.
- **Snap to edges.** While you draw, move or resize, the edge you are dragging snaps to a nearby window or screen edge within 8 screen pixels, with a thin guide line.
- **Hold Alt (Option on a Mac)** to turn snapping off for a moment, both the window highlight and the edge snap. A **Snap** chip next to the presets turns it off for the whole session.
- The window list now carries the stacking order, so the front window wins where windows overlap. Windows are clipped to the screenshot and tiny ones are ignored.
- The Windows window list now reports each window's exact frame (DPI aware, without the invisible shadow border) and skips minimised and hidden windows. Before, it had names only, so there was nothing to snap to.

## Fixes and changes
- The X, Y, Width and Height boxes show whole pixels while you drag.
- CI runs `node --test tests/js`, which covers the snap geometry: the window under a point, the aspect fit, edge targets and snapping. Rust tests cover the Windows window parser.

## Check it on your Mac
1. Run `demolens sources`. Each window should have `x`, `y`, `w`, `h` and a `z` (0 is the front window). Send me the JSON if a frame looks wrong.
2. Open the source picker, go to Area, and hover over a few windows. The highlight should sit exactly on the window. Click one, then press Record and check the clip matches.
3. Try 16:9 and 9:16, hold Option while hovering, and drag a corner near another window's edge.
4. With two overlapping windows, check that the one in front is the one that highlights.

## Honest limits
- The macOS stacking order is taken from the order ScreenCaptureKit lists windows, which I believe is front to back but could not confirm on hardware. If the wrong window highlights where two overlap, tell me.
- Windows frames and stacking are untested on a real PC. Only the parser is tested, on CI.
- The area is picked on a screenshot of the primary display, so windows on other displays are not offered.
- Snapping uses the screenshot taken when the Area tab opens. Windows you move afterwards are not tracked until you reopen the tab.
- While a selection exists, hovering over it moves it rather than highlighting a window. Click outside it to snap to another window.
- Not notarised; macOS asks for permissions again after each update. System audio still needs a loopback device.
